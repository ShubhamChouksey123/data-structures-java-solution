## LLD Round Prep Checklist

Since no Enterpret-specific candidate reports were found (small company, no Glassdoor/LeetCode-discuss coverage as of this research pass), this is a **general LLD-round readiness checklist** rather than confirmed reported questions. Re-usable practice material already exists in the separate [`low-level-design`](https://github.com/ShubhamChouksey123/low-level-design) repo — link out to specific problems there rather than re-solving inline.

* [ ] **Confirm local coding environment now, not day-of** — IDE, language runtime, and any library you'd reach for (e.g. a concurrency/collections library) installed and smoke-tested, per the invite's explicit instruction.
* [ ] **Requirements-gathering opening**: practice stating functional + non-functional requirements and clarifying scope *before* writing a class — a "real-life scenario" prompt (vs. a canned DSA problem) means the requirements themselves are part of what's being evaluated.
* [ ] **Core OOP + design-pattern fluency**: be ready to name and justify a pattern choice (Strategy, Factory, Observer, Decorator) as it comes up naturally, not recite them unprompted.
* [ ] **Re-solve 2–3 classic LLD prompts cold, narrating trade-offs out loud** (e.g. Parking Lot, Elevator System, Rate Limiter, Splitwise/expense-sharing — the "real-life scenario" framing suggests something in this family rather than an abstract algorithmic twist). Practice bank: [`low-level-design`](https://github.com/ShubhamChouksey123/low-level-design) repo.
* [ ] **Extension-question readiness**: after a working design, rehearse "how would you add feature X" or "how would this change under concurrent access" — LLD rounds commonly probe extensibility after the first pass, not just correctness.
* [ ] **Trade-off articulation under pushback**: pick one deliberate design choice per practice round and defend it when challenged (e.g. interface segregation vs. a simpler single class, in-memory vs. persisted state) — matches the invite's explicit "trade-offs" evaluation criterion.
